## R03: baseline, authorization and implementation

Before this repair the browser mapped every loaded thread row and every correlated agent directly into React elements. There was no scroll-window implementation in these list renderers. The conversation's bounded projection did not provide a reusable variable-height list window for these surfaces.

With complete lineage metadata, the checkpoint browser build populated 10,000 threads in approximately **1.73 s**, retained approximately **70,335 DOM elements** across the document, and took approximately **31 ms** for subsequent scroll and focus actions. With 10,000 correlated agents, ingestion took approximately **113 ms**, switching to Agents approximately **1.14 s**, subsequent scrolling approximately **32 ms**, and the combined document retained approximately **211,076 DOM elements**. These are single local fixture measurements, not percentiles, live-provider timings or cross-machine guarantees.

An earlier incomplete-metadata fixture took approximately 21.5 s and triggered approximately 10,000 metadata reads. That result includes lineage discovery and is not presented as list-rendering cost. The complete-metadata run separates that dependency. A production repair must preserve the existing lineage/admission policy rather than introducing an unrelated hydration limit.

Deleting data or replacing scroll navigation with an arbitrary displayed-entry cap would violate the requested behavior. CSS containment alone would retain all React elements and DOM residency. The user authorized shared windowing and the combined 340-line cap with “Commit current changes than authorized for R03”. The checkpoint was committed before production implementation.

[ScrollWindow](../../web/src/app/ScrollWindow.tsx) now supplies one residency mechanism to thread-member lists and Inspector Agents. It measures only resident rows through ResizeObserver, keeps scalar heights keyed by existing semantic identity, estimates unseen rows at 40 px, and renders the viewport plus 400 px overscan and any focused, selected-text or open-menu rows. Spacer heights preserve the complete logical scroll range. The existing parent scrollbar remains authoritative, including independent project bodies and nested sections. Stable keyed rows and the existing viewport-state owner retain disclosure state. Existing pending-row animations use the browser timeline across recycling. No additional timer, protocol store, alternate row renderer, destination limit or hydration policy was introduced.

A weak registry exposes logical tree entries to the existing tree keyboard handler; its DOM-only enumeration was replaced. Home/End, arrows and Tab can materialize a target before focusing its existing control. Row focus and text selection are retained during scrolling; context-menu dismissal restores the actual trigger. The window captures a semantic anchor and offset before prefix geometry changes, preserving the visible position during insertion and offscreen card-height changes. ResizeObserver and event subscriptions are disconnected on each effect cleanup. Scalar heights are removed when their keys leave the logical list. The existing browser/server layout-effect distinction was moved into the shared module and reused by App.

Final large-list fixture measurements: **533.3 ms** thread hydration versus the recorded **1733.8 ms** baseline; **70.0 ms** Agents switching versus **1135.1 ms**. Agent ingestion was **93.4 ms**. End navigation took **33.3 ms**; no scroll-latency improvement is claimed. The sampled states retained **37 thread rows / 605 document elements** before Agents, and **30 agent cards / 2389 document elements** afterward, versus approximately 70,335 / 211,076 baseline document elements. Insertion anchor drift was zero; offscreen variable-height reflow drift was **0.344 px**. The nested-project fixture retained **19 rows** for 10,000 threads, including 2,000 in a nested section, and preserved the outer scrollbar position. These remain local fixture results, not percentiles or live-provider guarantees.

The browser qualification enforces fewer than 100 resident thread rows and agent cards in the measured states, fewer than 10,000 combined document elements, complete first/last reachability, distinct logical arrow targets, preserved focus/menu/selection/expansion, anchor drift at most 1 px and faster hydration/tab switching than the recorded local baselines. Four DPRs, a 20 px root font and coarse pointers retain last-entry reachability and no horizontal document overflow. Data and scalar index/prefix processing remain proportional to loaded entries; this change bounds row/DOM/Markdown residency, not the authoritative inventory. Project and section headers retain their existing presentation; this is member-list windowing, not a new group-catalog renderer. Real screen-reader certification and the entire native visual signoff matrix are not claimed.
