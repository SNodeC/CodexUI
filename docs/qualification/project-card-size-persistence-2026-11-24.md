# Native project-card size persistence qualification

This follow-up applies sections 4, 6, 20 and 21 of the [canonical native suite](native-test-suite.md#banner) to restart persistence. The [original resize qualification](project-card-resizing-2026-11-24.md) records the initial implementation, which retained heights only while its presentation rows lived. This follow-up supersedes that restart limitation.

## Ownership and correction

The invariant is that a chosen project height is a persistent UI preference, like expansion, owned by the same server and stable project presentation identity. The existing path is NodeGraph → NodeGraphUiAdapter → ThreadPane reconciliation → ThreadTreeItem → projectBodyHeight → outer delegate and project body viewport. Resizing already converges on one operation for pointer, keyboard and accessibility input; that operation now saves the chosen limit using the existing QSettings scope. Reconciliation restores it when creating a project row or changing servers. A server change participates in the existing layout and pagination refresh conditions so restored geometry becomes visible immediately.

Deleting or reshaping the existing in-memory height cannot retain it across processes. The correction therefore connects that field to existing settings storage; it introduces no second renderer, persistence service, timer, cache, member flag or geometry calculation. It replaces the transient-only lifetime policy. The one local boolean names the existing server-change condition so restoration and layout use that same decision. The existing height calculation applies one-row and currently loaded-content bounds without overwriting the saved limit during a content-only refresh.

## Verification scope

The restart fixture launches distinct writer and reader application processes sharing only an isolated settings directory. The writer chooses three-row and five-row heights through native keyboard input and collapses the first project before exit. The reader verifies expansion restoration, opens the collapsed project and checks both heights, the untouched eight-row default, stable identity after renaming/reordering, a two-row content clamp and recovery, and independent settings when switching to another server and back. It runs at requested widths 260/440 and fonts 10/16 for DPR 1.0/1.25/1.5/2.0. Qt minimum hints widen the requested 260-pixel fixture to 299 pixels at font 10 and 429 pixels at font 16; requested 440 remains 440. All fixtures are 1100 logical pixels high.

The existing thread-pane suite still exercises mouse, keyboard and accessible resizing, following-card geometry, selection, focus, scroll, font changes, interrupted gestures, visibility feedback and pagination. Width/font cases now use distinct server or project identities so persistent preferences cannot leak between otherwise independent fixtures. Assertions were retained. The test executable's dispatch uses a single final return for normal, performance and restart phases; every normal test still executes after an earlier failure.

Execution uses Xvfb with `QT_QPA_PLATFORM=offscreen`, isolated preferences and task-local temporary files. Sandbox attempts could not bind Xvfb sockets and are not accepted as Xvfb qualification, even when offscreen child tests ran. Final qualification runs outside that sandbox and checks the wrapper exit status as well as every child result. The Xvfb log contains nonfatal xkbcomp warnings. Backend data is simulated; this does not claim a live server restart, screen-reader session, browser parity or desktop compositor qualification.

Evidence is under `/tmp/codex/artifacts/CodexUI/project-card-size-persistence/`; the build and evidence are retained for review and can be removed after acceptance. `final-matrix.log` records the thread-pane and 10,000-thread gesture checks; `final-shell-dpr-*.log` records actual ShellWidget resizing during graph updates and the workspace-action lifetime regression; `results.json` records process statuses. `captures/` contains 32 before/after restart widget images, and `review/` contains eight comparison sheets.
