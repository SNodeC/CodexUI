### Section geometry clarification

The browser measurements in the populated audit fixture were **38 px standalone header, 32 px nested header, 32 px standalone member and 32 px project member**. Although `.nested-section > header` declares a 24 px minimum, the later `.project-thread-body` rule overrides it with the project row height. Any earlier description of the actual nested header as 24 px was incomplete. See [styles.css](../../web/src/styles.css), lines 274–325.

Browser and native therefore do not share exactly the same spacing failure: the native fixture clearly has 40 px standalone member rows; the browser fixture has equal member heights with a taller standalone header. The specification deliberately requires standalone sections to be enclosing cards and nested sections to be headings. That representational distinction is not itself a defect. Browser header density remains a design consistency consideration, not a separately counted proven error.

## Architectural conclusion and repair sequence

The recurring invariant is that one visible concept should have one geometry policy, one interaction owner, one semantic identity and one feedback/admission policy. Current problems occur where individual consumers independently apply those policies: native grouped row geometry; browser menu/selector keyboard ownership; Copy outcome presentation; draft editing versus submission authority; protocol disclosure identity; and selection semantics.

First reconcile the contradictory section specification and identify the intended shared density. Then correct the existing owners: menu event handling, draft preservation, stable protocol identity, availability and feedback. Reconcile group geometry as a complete sizing/painting/hit-testing change. Remove obsolete section controls if confirmed by the current contract. Qualify the five risks separately before treating them as established defects. No new framework, generic menu engine, additional presentation layer or independent state store is justified by this inventory.
