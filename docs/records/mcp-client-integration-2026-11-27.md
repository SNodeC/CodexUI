## Authority, lifecycle and local correction

MCP transports, initialization, negotiated capabilities, server catalogs, tool execution and model tool definitions belong to the upstream Codex backend. CodexUI is an AISuite app-server frontend. `ClientRuntime` retains each typed reverse request by its exact graph interaction and provider generations; `NodeGraph` owns pending state. `NodeGraphUiAdapter` projects that state; `ShellWidget` and `PendingRequestDialog` collect authored values. Submission returns through the existing `ResolveInteraction`, policy validation and typed `CodexBridge::respond` route. Successful delivery or `serverRequest/resolved` retires the exact request; provider changes clear retained runtime requests and invalidate graph interactions. No second MCP connection or tool registry belongs in this frontend.

The violated local invariant was: **only an explicit authored decision can produce a terminal response, and an open review must not outlive its authoritative pending interaction**. Previously every dialog rejection, including Escape and window dismissal, became protocol Cancel. Resolved interactions left their review visible with a disabled Resolved button.

The correction moves Cancel creation to the explicit button action and removes generic rejection's implicit response. Escape/window dismissal now sends nothing. The existing shell graph projection closes a review when its exact request disappears or enters recovery after connection loss. Controller loss continues to disable submission while retaining the open editor. The existing request identity, single response route, policy validation and local draft/submission ownership remain in place. Shared approval reviews also close when their graph request ends. No timer, cache, protocol flag, registry or response-forwarding path was added. One Qt connection makes a validation warning end with its owning review; the regression first reproduced an orphaned warning and then passed after this correction. No additional protocol state is retained.

Reduction alone cannot preserve both explicit Cancel and nonterminal dismissal: the button signal must author Cancel separately from Qt's common rejection exit. The growth estimate before implementation was below 25 production lines. The metadata follow-up estimate was fewer than 40 additional production lines; it adds net 35. The final warning-ownership correction adds one net production line. Combined actual production: **66 added / 22 removed, net +44**. Tests: **290 added / 17 removed, net +273**. Documentation is accounted separately from production and tests.

The new widget checks exercise dismissal, Escape, authoritative resolution, connection closure, independent pending requests and one exact Cancel action for the remaining request. Existing schema controls and validation were already present in merged `d71acef`; progress retention was already present in `f2c4085`. These earlier changes were inspected, not claimed as new work.

## Boundaries established in the matching upstream source

The executable backing PID 1 resolves to `/usr/lib/chatgpt/resources/codex`; its reported version is `0.171.0-alpha.13`. PATH's `codex` reports `0.162.1`. AISuite's generated manifest is pinned to `rust-v0.162.1`. These are distinct facts; the binding version does not identify the active backend. The available exported `0.171.0-alpha.13` schema and the corresponding official release source were inspected. No backend source checkout or supported mutation interface for these missing capabilities was available in this task. Modifying upstream Codex is explicitly prohibited. No additional checkout was created and no upstream source was modified. Missing upstream interfaces remain limitations; no local substitute or parallel MCP client is authorized.

- **Elicitation:** the upstream modern continuation driver parses the whole round, assigns unique request identities and joins independent requests. The app-server maps a turn-transition error to Cancel, malformed/error/dropped client responses to Decline, and successful client responses to their authored action. CodexUI separately had the now-removed dismissal-to-Cancel conversion. These are possible origins established by code, not an attribution of earlier observed cancellations. The current form/rounds/parallel calls returned deadline errors; the user explicitly reported that no dialog appeared. No live request/response trace establishes the cause of that absent dialog or the provenance of earlier cancellations. CodexUI's source opens elicitation reviews through Requests/Review rather than automatically opening a modal; the UI surface observed during the live calls has not yet been identified, so the missing dialog is not attributed to either CodexUI or the chat host. See [request continuations](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/rmcp-client/src/request_input.rs) and [app-server response conversion](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/app-server/src/bespoke_event_handling.rs).
- **Dynamic tools:** the upstream transport records tool-list revisions before later responses. The authoritative client catalog coalesces refreshes, paginates the existing list operation and checks notification revisions before publication; failed refreshes retain the previous catalog. Ordinary-server refresh is gated by `config.client.mcp_tool_list_changed`, populated from `Feature::McpToolListChanged`. This flag's current runtime value was not observed. CodexUI cannot repair the model's catalog by retaining its own definitions. Native add/remove changed discovery cursors but never offered `dynamic.tool`; the exact reason for the inactive model refresh remains unproven. See [connection-manager gate](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/codex-mcp/src/connection_manager.rs), [catalog publication/races](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/codex-mcp/src/client_tool_catalog.rs), [transport revisions](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/rmcp-client/src/tool_list_changes.rs), and [feature projection](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/core/src/config/mod.rs).
- **Tasks:** upstream `McpServerToolCallParams` exposes thread, server, environment, tool, arguments and metadata, with no protocol task augmentation. The backend constructs ordinary call parameters without task options; initialization builds client capabilities without task support. The inspected app-server operation catalog has no MCP task status/result/list/cancel methods. Required calls therefore cannot be fixed by adding business arguments. Ownership, TTL, terminal transitions and task updates remain unimplemented at the backend boundary and unverified natively. See [MCP app-server contract](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/app-server-protocol/src/protocol/v2/mcp.rs), [MCP call construction](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/rmcp-client/src/rmcp_client.rs) and [MCP initialization](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/codex-mcp/src/rmcp_client.rs).
- **Prompts/completion:** no prompt list/get, completion or argument-context operation exists in the inspected app-server catalog or this model's callable tools. Multi-message prompts and embedded prompt resources cannot be exercised through that missing boundary. No intentionally user-command-only CodexUI implementation was found; absence is not presented as an intentional restriction. See [app-server operations](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/app-server-protocol/src/protocol/common.rs).
- **Progress/subscriptions:** ordinary progress and resource-update notifications reach the upstream logging handler, not a model-visible progress/subscription interface. CodexUI already retains app-server `item/mcpToolCall/progress` notifications, but this cannot create notifications absent from the backend. The app-server event-stream start/stop API describes named event streams rather than `resources/subscribe`/`unsubscribe`; it is not a substitute for showcase's counter subscription. No native resource-subscription or unsubscribe control is exposed. See [ordinary notification handling](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/rmcp-client/src/logging_client_handler.rs), [event streams](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/codex-mcp/src/event_stream.rs) and the MCP app-server contract above.
- **Identity, errors/media:** the app-server status shape can carry server identity, capabilities and list metadata, and CodexUI retains the received payload. It does not provide a directly known negotiated MCP version; none is reported here. The model has no status accessor. Audio omission is an explicit input-modality gate, and Code Mode removes private `_meta`. Native results preserved content annotations, resource-link properties, images and embedded resources. No server corruption or decoded-audio/display success is claimed. See [audio gate](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/core/src/mcp_tool_call.rs), [Code Mode output filtering](https://github.com/openai/codex/blob/rust-v0.171.0-alpha.13/codex-rs/tools/src/tool_output.rs) and the MCP app-server contract above.

Upstream modification is prohibited, so these are limitations of the available integration rather than authorized implementation work. Native Accept/Decline/Cancel, completed rounds/parallel requests, task/resource/prompt input and notification delivery remain outstanding. Earlier cancellation provenance remains unknown. The actual negotiated version must be forwarded from initialization before a client can truthfully display it.
